# 单张图（快速档 / 精品档）

## 适用

- 要一张新图，可以只有文字，也可以带参考图。
- 不适用：
  - 要保留某张已有图并修改，走 `flows/edit-refine.md` 或 `flows/redesign.md`。
  - 要多张一致的图，走 `flows/series-project.md`。

## 选档

| 档 | 信号 | 差异 |
|---|---|---|
| 快速档 | 示意、草稿、头像、配图，描述短，没有强调质感 | 第 2 步只补镜头、画风、光；第 3、4 步可以跳过，但第 3 步的冲突检查在冲突明显时仍要做；验收只查需求、人体和明显的结构错误 |
| 精品档 | 描述长，强调张力、质感、“杰作”，给了参考图，或用户明显会逐细节挑剔 | 全部步骤都做；预期多轮，先用重生成定大局，再用精修收细节 |

选定后回复：“走 单张图·<快速档/精品档>，依据：用户提到 <原话>；决策模式：<询问/自主/混合>；下一步执行第 0 步”。

## 第 0 步：准备

1. 确认输出目录和文件名，默认放在当前工作区。
2. 确认画幅比例。用户没说时按用途定：横幅场景用 16:9，人物立绘用 2:3，头像用 1:1。
   - 比例只能写在提示词里（Asset type 行）。内置生图工具没有尺寸参数，实际像素由模型决定。
3. 列出参考图，每张写清：
   - 借什么：角色设计、姿势、镜头、画风、某个道具。
   - 不借什么：服装、背景、版式、无关人物、黑边、画风。
   - 参考图里只有局部有用（例如只要鞋子）时，先裁剪，只把裁好的局部喂进去。
4. 询问模式下也只问《决策点》表里的项。镜头、手、光这些维度由你补全，不逐项问用户。

## 第 1 步：需求拆解

把用户原话拆成下表，写在回复或草稿里：

| 项 | 内容 |
|---|---|
| 主体 | 谁或什么，固定外观 |
| 动作与事件 | 正在做什么，力从哪里来、到哪里去 |
| 气质与情绪 | 用户用的形容词 |
| 强调词 | 用户特别强调的词（如“冲击力”“优雅的危险”），逐个翻译成画面手段 |
| 画风与写实刻度 | 先记下用户原话，第 2 步读维度卡定档 |
| 画幅 | 比例、主体大致位置 |
| 明确禁止 | 用户说了不要的 |

强调词翻译示例（通用）：

- 冲击力：对角线动势、低机位、伸出肢体的透视缩短、风吹动布料和头发、能量特效、明暗对比。
- 优雅：长线条、柔韧的曲线、精致的末端（指尖、鞋跟、发梢）、克制的特效。
- 危险感：尖锐的轮廓、冷色轮廓光、锐利的视线落点。

## 第 2 步：补全未提及的维度

读取 `catalog/README.md`，按其中的选卡规则逐项补全。快速档只补镜头、画风、光；精品档全部补：

- 镜头构图：景别、机位高度、水平角度、焦段、主体位置与占比、必须入框的元素、留白方向。
- 身体与手：动作线、躯干、四肢、每只手的握法、接触点、视线落点。
- 面部表情：程度和排除项。
- 服装道具：材质、结构、尺度，以及“没有什么”。
- 光影环境：主光、轮廓光、特效光落在哪；前景、中景、远景各放什么。
- 物理：接触阴影、重力、透视一致。

补全原则：

- 补的是让画面成立的必要信息。用户没暗示的人物、道具、剧情不要加。
- 用户给了具体描述的地方，原样保留并规格化，不替换成你的偏好。

## 第 3 步：物理与几何推演（精品档必做）

逐项自问，并把结论写进提示词：

1. **受力链**：哪个部位推或拉哪个物体，接触面是什么（鞋底、掌心、指腹）。
2. **交点与直线**：线、绳、杆、箭这类要求直的东西，从哪里到哪里，在哪一点汇合。
3. **肢体长度**：弯曲或透视缩短的肢体，各段长度是否和伸直的一侧相等。
4. **重力与悬浮**：哪些东西允许悬浮（光、特效），其余全部受重力。
5. **冲突**：需求之间是否打架。例如长裙配高抬腿、拖地披风配奔跑、细高跟配蹬踏。
   - 发现冲突，先在提示词里给出解法（高开衩、裙摆向后飘），不要让模型自己悄悄取舍。
   - 解法会改变用户设定的，先问用户。

## 第 4 步：易画性改造（精品档必做）

以下形态模型很难画对。预判到就先改形态，不要等失败后再加强调词：

| 难画的形态 | 改法 |
|---|---|
| 又细又长的直物（箭杆、长杆、细剑、绳线） | 加粗加体积；加贯穿全长的棱边；加等距分段标记；缩短到合理长度 |
| 两段线要汇于一点（弓弦、吊索） | 写明唯一交点和“两段各自笔直” |
| 需要精确计数的小物（饰品笔画、扣子） | 写 exactly N，并描述每一个；验收时放大核对 |
| 不合常理的动作（用脚蹬物、单手托重物） | 写明道具上没有辅助结构，动作是角色自身能力的展示 |
| 道具随镜头旋转后的透视 | 单独描述道具朝向和透视；提前告诉用户这一步难，可能要多试几次 |

## 第 5 步：写提示词

- 语言：英文。分段标签和用词规则在第 2 步选卡时一并读取的 prompt-language 卡里。
- 存成文件，例如 `prompts/<name>.txt`；不要把长提示词直接写在命令行里。
- 模板如下。不用的行删掉，不留空标签：

```text
Use case: <stylized-concept | photorealistic-natural | illustration-story | ...>
Asset type: <用途，如 finished cinematic key visual>. <比例，如 16:9 landscape, full-bleed>.
Input images: Image 1 is <角色>: take only <要借的>. Do not take <不借的>.
Style/medium: <写实刻度锚定词>
Rendering rules: <皮肤 / 头发 / 材质 / 光的渲染规则>
Subject: <固定外观：脸、发、体型、服装、配饰>
Props: <道具形态、材质、尺度；写明 has NO ...>
Scene: <环境：前景 / 中景 / 远景>
Framing: <景别、机位高度、水平角度、焦段；主体位置与占比；必须完整入框的元素>
Pose and interaction: <动作线 → 躯干 → 腿 → 手臂 → 每只手的握法与接触点 → 头与视线>
Geometry: <直线、交点、长度相等等几何约束>
Expression: <程度 + 排除>
Motion: <风、布料、头发、粒子>
Lighting: <主光 / 轮廓光 / 特效光，落在哪、在哪里减弱>
Physics: <接触阴影、重力、无实体悬浮、透视一致>
Avoid: <针对本图风险的排除项>
```

## 第 6 步：执行

```text
python <skill目录>/scripts/gen.py --prompt <提示词文件> --out-dir <输出目录> --name <产物名> [--ref <参考图>]...
```

- 依赖：本机已登录的 Codex CLI，以及 Python 3.10+ 标准库，不需要第三方包。
- `--ref` 的顺序就是提示词里的 Image 1、Image 2……，两边必须一致。
- 产物保存为 `<产物名>-vNNN.<扩展名>`，旁边会生成同名 `.prompt.txt`，记录实际发送的提示词和参考图。
- 先用 `--dry-run` 检查拼装结果。这一步不调用 Codex，不消耗额度。
- 判断成败只看脚本是否打印“完成”以及输出文件是否存在。终端里的 PowerShell profile 报错和生图无关。
- 一张图一次调用；不同的图不要合并成一次调用。

## 第 7 步：验收（必须自己看图）

逐条检查，小细节放大核对：

- [ ] 用户需求逐条：每个强调词是否落到了画面上。
- [ ] 人体：每只手五根手指；关节方向正确；肢体各段等长；握持有真实接触；不接触的地方留有空隙。
- [ ] 道具：直的是否笔直；交点是否唯一；计数是否正确；是否多出了辅助结构。
- [ ] 物理：接触阴影、重力、透视一致、光向一致、倒影对应。
- [ ] 画面：比例、裁切、主体占比、前景是否过近、背景是否过空、有没有文字或水印。
- [ ] 写实刻度：是否落在目标档，有没有滑到相邻档。

## 第 8 步：返修决策

| 问题 | 处理 |
|---|---|
| 构图、主体位置、镜头角度大幅不对 | 改 Framing 后重新生成；不要用编辑去挪 |
| 姿势小幅调整（前倾、手型、视线） | 以当前图为底图，用编辑模式改 |
| 局部物件错（手、线、计数、颜色） | 转 `flows/edit-refine.md` |
| 写实刻度不对 | 先编辑一次；改不动时转 `flows/redesign.md` |
| 同一个错误连续出现两次 | 换形态或换描述方式（回到第 4 步），不要只加强调词 |
| 用户反馈有歧义 | 先用自己的话复述，等用户确认后再改 |

## 决策点

| 决策点 | 选项 | 自主默认 | 即使在自主模式也要问 |
|---|---|---|---|
| 档位 | 快速 / 精品 | 按选档表中的信号判断；拿不准时选精品 | — |
| 画幅比例 | 16:9 / 2:3 / 1:1 / 其他 | 按第 0 步的用途默认 | 用途决定不了比例，例如要拿去印刷 |
| 写实刻度 | 维度卡里的 6 档 | 按用户用词就近定档，并排除相邻档 | 用户用词同时指向两档，例如“超写实”又“二次元” |
| 参考图借用范围 | 借哪些、不借哪些 | 只借用户点名的要素，其余一律不借 | 用户没说参考图用来做什么 |
| 冲突解法 | 第 3 步列出的解法 | 选最不改变用户设定的解法，在交付时说明 | 解法会改变用户明确给出的设定 |
| 返修手段 | 编辑 / 重生成 / 转精修 / 转改造 | 按第 8 步的决策表 | 重生成可能让用户已认可的脸或服装变化 |
| 是否继续迭代 | 交付 / 自动返修 / 列为可选方向 | 结构性缺陷自动返修，最多 2 轮；审美取舍列为可选方向 | 超过 2 轮 |

## 交付口径

- 给出成图路径和提示词文件路径。
- 用表格对照需求，标出做到 ✅ 和没做到 ⚠️ 的地方。没做到的照实说，不美化。
- 自主或混合模式下，列出《我替你做的决定》：决定、理由、怎么推翻。
- 列出《可选方向》：1–3 个下一步方向，每个说明代价。例如“编辑稳，但质感提升有限”“重生成能明显提升质感，但脸可能变”。
