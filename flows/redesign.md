# 改造已有图

## 适用

- 已有图要做较大的改动，同时保留一部分：
  - 换装、换形态。
  - 换画风或写实刻度。
  - 转镜头。
  - 重排构图。
  - 让主体腾出空间。
- 不适用：只改局部，走 `flows/edit-refine.md`。

## 第 1 步：列保留项和替换项

| 保留（从哪张图来） | 替换（换成什么、从哪张图来） |
|---|---|
| 例：面部、动作、环境氛围、画风（当前图） | 例：服装、发色、配色（新设定图） |

- 每一项都要标出来源图，后面写 Input images 时照这张表写。
- 新设定图是平面线稿或插画时，写明只借设计，不借画风：take ONLY the design, NOT their drawing style。
- 有不确定的保留项（发色、配饰、尾巴、鞋）时，按《决策点》表处理：询问模式问用户，自主模式按默认执行并在交付时说明。

## 第 2 步：选手段

| 改动类型 | 手段 |
|---|---|
| 只改画风或写实刻度，姿势和构图不变 | 先用编辑模式，以当前图为底图试一次 |
| 小幅改姿势（压低上身、手型） | 编辑模式，可加一张姿势参考图 |
| 换装，且新服装和原动作有冲突 | 以当前图为参考重新生成 |
| 转镜头、挪主体、改构图 | 以当前图为参考重新生成；不要用编辑去挪 |

回复：“走 改造，依据：用户提到 <原话>；决策模式：<询问/自主/混合>；手段：<编辑/重生成>；下一步列保留和替换”。

## 第 3 步：冲突预判与画面重排

先读取 `catalog/README.md`，按“改造已有图”一行选卡（全部 7 张）。

- **服装和动作的冲突**：拖地长裙配高踢、长披风配奔跑、繁复袖子配拉弓等。
  - 先给出解法，例如高开衩、裙摆向身后飘、袖口收紧。
  - 解法会改变设定图的，告诉用户。
- **新增元素要占空间**（尾巴、翅膀、长外袍）：
  - 安排它们飘向哪一侧，不和主体动作挤在一起。
- **主体占比**：
  - 镜头拉远后主体容易变小、背景变空。
  - 写明主体占画幅宽度大约多少，通常 70%–80%。
  - 远景要补出层次。
- **转镜头**：
  - 写明相对纯侧面转了多少度，以及因此能看到什么，例如双眼、双肩、胸口朝向镜头。
  - 道具的朝向和透视要单独写。实践中模型常常只转人、不转道具。

## 第 4 步：写提示词

```text
Use case: <identity-preserve | style-transfer | stylized-concept>
Asset type: <用途>, <比例>.
Input images:
- Image 1 = <当前图>. Keep from it: <保留项逐条>.
- Image 2 = <新设定图>. Take ONLY <服装/形态设计>, NOT its drawing style.
- Image 3 = <姿势/镜头参考>. Copy only <镜头/姿势>. Do NOT take <服装、人物、背景、黑边等>.
Change ONLY: <替换项逐条>.
Style/medium: <写实刻度锚定词，和当前图一致或新目标档>
Character / Outfit: <新服装从上到下逐件写；材质；计数；排除旧服装的元素>
Framing: <新镜头：角度（离纯侧面多少度）、机位、占比、必须入框的元素>
Pose and interaction: <动作；肢体各段等长；每只手>
Props: <道具形态；朝向与透视；has NO ...>
Scene: <环境；退让给主体的空间；前景不遮挡>
Lighting: ...
Avoid: <旧服装元素、相邻写实档、裁切、前景杂物等>
```

## 第 5 步：执行

```text
python <skill目录>/scripts/gen.py --prompt <提示词文件> --out-dir <输出目录> --name <产物名> --ref <Image 1> [--ref <Image 2>] [--ref <Image 3>]
```

- `--ref` 的顺序必须和 Input images 的编号一致。
- 依赖本机已登录的 Codex CLI，以及 Python 3.10+ 标准库。判断成败只看脚本是否打印“完成”以及输出文件是否存在。终端里的 PowerShell profile 报错和生图无关。

## 第 6 步：验收

- [ ] 保留项逐条核对：脸是不是同一个人、画风有没有漂移、环境氛围在不在。
- [ ] 替换项逐条核对：新服装的每个部件是否齐全，旧服装的元素是否残留。
- [ ] 和设定图的偏差：逐一列出，并说明原因，例如“为配合动作，裙子收短了”。
- [ ] 镜头和构图：角度是否到位、道具是否跟着转、主体占比、裁切、前景。
- [ ] 通用检查：五指、肢体等长、道具结构、物理、无文字水印。

## 第 7 步：后续

- 局部还有小错，转 `flows/edit-refine.md`。
- 人转过来了、道具没跟着转这类难点，坦白告诉用户，再给出选项：多试几次重生成，或接受现状。

## 决策点

| 决策点 | 选项 | 自主默认 | 即使在自主模式也要问 |
|---|---|---|---|
| 不确定的保留项（发色、眼色、翅膀、配饰、鞋） | 跟随新设定 / 保留当前图 | 和新设定冲突的项跟随新设定；新设定没有涉及的项保留当前图 | 用户的话可以两种理解，例如“换衣服”是否连发色一起换 |
| 新设定里有、当前图没有的元素（尾巴、披风） | 加 / 不加 | 加，并安排到不挡住动作的位置 | — |
| 服装和动作的冲突 | 改服装 / 改动作 | 优先改服装细节（开衩、飘向），保住用户认可的动作 | 两边都是用户明确要求的 |
| 手段 | 编辑 / 重生成 | 按第 2 步的表 | 重生成可能让用户认可的脸变化 |
| 转镜头角度 | 小转 / 大转 | 相对上一版多转 30° 左右 | — |
| 主体占比与环境让渡 | 占比数值 | 70%–80% | — |

## 交付口径

- 给出路径和对照表：保留项、替换项、和设定图的偏差、未达成项。
- 有两种以上后续方案时，说明各自的代价，例如编辑能保住脸但改动有限，重生成改动大但脸可能变。
- 自主或混合模式下，列出《我替你做的决定》：决定、理由、怎么推翻。
- 列出《可选方向》。
