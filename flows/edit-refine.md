# 精修已有图

## 适用

- 已有一张基本满意的图，只改局部：手、线、计数、颜色、某个物件、前景杂物、腿型等，其余保持不变。
- 不适用：
  - 改构图、主体位置、镜头角度、服装主体或画风：编辑模式通常改不动，走 `flows/redesign.md`。

## 两种手段

| 手段 | 什么时候用 |
|---|---|
| 编辑模式 | 默认手段。底图作 Image 1，只描述改动 |
| 局部贴回 | 编辑后目标区域对了，但别处也跟着变了（脸、嘴、背景），用旧图为底只贴回目标区域 |

回复：“走 精修，依据：用户提到 <原话>；决策模式：<询问/自主/混合>；本轮改动：<一处>；下一步写编辑提示词”。

## 第 1 步：定位并描述“现在的错”

- 放大看问题区域，用具体事实描述，不写“不自然”这种感受词：
  - 数量：多了一笔、少了一根手指。
  - 位置：两段线没有交在同一点，下段落在胸口。
  - 接触关系：手指捏着杆身，本应不接触。
  - 尺度：物体比头还大，本应约两指宽。
- 用户的反馈有歧义时，先用自己的话复述，等确认后再写提示词。例如“一样长”可能指透视下各段长度相等，而不是把腿伸直。

## 第 2 步：确认适合编辑

- 改动只涉及局部，并且不需要移动主体或镜头，才用编辑。
- 小幅的姿势调整（上身前倾、手型、视线）可以编辑；大幅挪位置不行。

## 第 3 步：写锁定清单和改动

写之前读取 `catalog/README.md`，按“精修已有图”一行选卡：只读改动涉及的那一张，再加 prompt-language。

- 一轮只改一处；两处改动高度相关时，最多两处。
- 锁定清单逐项列出，不只写“其他不变”：人物身份、脸、表情、发型、服装、姿势、其他道具、背景、光、构图、比例。
- 模板：

```text
Use case: precise-object-edit
Input images: Image 1 is the edit target. [Image 2 shows the correct <物件>.]
Edit: change only <目标>. It currently <现在的错，具体到数量、位置、接触>. Make it <目标状态，写几何与接触：唯一交点、各段笔直、不接触、相对尺度>. <被移除区域用周围的什么填补>.
Keep everything else exactly unchanged: same <逐项锁定清单>, framing, lighting and aspect ratio. Do not redraw or restyle anything else. No text, no watermark.
```

- 改的是手：分别写每只手的握法、手指摆位、接触点和“不接触什么”，并写 exactly five fingers。
- 改的是线或杆：写端点、交点、“each segment perfectly straight”。
- 改的是体型：写方向和健康边界，例如 more slender, elongated, healthy natural anatomy；同时锁定姿势和各段长度。

## 第 4 步：执行

```text
python <skill目录>/scripts/gen.py --prompt <编辑提示词> --out-dir <输出目录> --name <产物名> --ref <底图> [--ref <正确样例图>]
```

- 编辑类提示词不要加 `--spec`，固定设定会干扰“只改一处”。
- 底图必须是 `--ref` 的第一个，对应提示词里的 Image 1。
- 依赖本机已登录的 Codex CLI，以及 Python 3.10+ 标准库。判断成败只看脚本是否打印“完成”以及输出文件是否存在。终端里的 PowerShell profile 报错和生图无关。

## 第 5 步：对比验收

- 和底图逐区对比：脸、手、背景、服装、光。
- 目标区域放大核对：计数、交点、接触。
- 结果判定：

| 结果 | 处理 |
|---|---|
| 目标对了，别处没变 | 通过 |
| 目标对了，别处变了 | 第 6 步局部贴回 |
| 目标没变或仍然错 | 换一种描述方式（换形态、换几何表述），不要只加强调词；连续两次失败就告诉用户这一处难，并给出替代方案 |
| 底图的构图被改了 | 放弃本次结果，检查锁定清单是否漏项 |

## 第 6 步：局部贴回

```text
uv run <skill目录>/scripts/patch_region.py --base <旧图> --source <编辑后的新图> --out <输出路径> --ellipse cx,cy,rx,ry [--rect x1,y1,x2,y2] [--feather 3] [--zoom <放大核对图路径>]
```

- 坐标单位是像素，以底图尺寸为准。看图估出目标区域，适当留一点边。
- 两张图尺寸不同时脚本会拒绝执行。确认构图一致后，才可以加 `--resize-source`。
- 脚本会打印改动外框，并可输出放大核对图。必须确认外框只落在目标区域内。
- 依赖：`uv`（脚本头部声明了 pillow，`uv run` 会自动安装）。
- 输出路径已存在时脚本会拒绝，不会覆盖。

## 决策点

| 决策点 | 选项 | 自主默认 | 即使在自主模式也要问 |
|---|---|---|---|
| 用户反馈的理解 | 复述确认 / 直接执行 | 反馈只有一种合理理解时直接执行，在交付时写明理解 | 反馈有两种以上合理理解 |
| 一轮改几处 | 1 处 / 2 处 | 1 处；只有两处高度相关时才合并 | — |
| 是否适合编辑 | 编辑 / 转改造 | 按第 2 步判断 | 转改造可能让脸或服装变化 |
| 漂移处理 | 局部贴回 / 重新编辑 | 目标对了、别处变了，就局部贴回 | — |
| 连续两次失败后 | 换形态 / 接受现状 / 转重生成 | 换一种描述或形态再试一次 | 换形态会改变用户的设定 |
| 体型、比例这类审美改动的幅度 | 小 / 中 / 大 | 小幅，保持健康自然 | 用户没给方向，例如只说“调一下腿” |

## 交付口径

- 给出新图路径，说明改了什么、怎么改的。
- 照实说明：哪些锁定项保持住了，哪里有轻微漂移，有没有用局部贴回兜底。
- 自主或混合模式下，列出《我替你做的决定》，例如对反馈的理解、改动幅度。
- 列出《可选方向》：还能继续修的点，以及每个点的代价。
