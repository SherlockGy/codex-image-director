# 方案探索

## 适用

- 某个形态还没定（配饰、道具、服装、伙伴生物、构图），用户要先看几个方向再挑。
- 核心：让方案之间**可比**。同一个底座，只换被探索的对象，用户才能看出差别出在哪里。
- 不适用：方向已定、只差细节，走 `flows/single-image.md` 或 `flows/edit-refine.md`。

## 第 1 步：定不变量和探索轴

| 项 | 写法 |
|---|---|
| 不变量 | 角色、镜头、光、背景、画风都固定，写成一段公共底座文本 |
| 探索轴 | 一轮只开一个轴（如形状、材质、佩戴位置），最多两个轴做少量组合 |
| 方向数 | 每轮 3 个左右；每个方向消耗一张图的额度 |

回复：“走 方案探索，依据：…；决策模式：<询问/自主/混合>；本轮探索轴：<轴>，方向：A / B / C”。

## 第 2 步：给每个方向写一句设计主张

- 一句话说清这个方向的核心想法，以及它和其他方向的区别。
- 派生设计（从已有元素演变出新物件，例如从角色伙伴演变出配饰）用这条原则：
  - **基因不变，形态重组**：保留源头的几个辨识特征（颜色、光感、标志性的线条），重新组合成目标品类自己的形态。
  - **第一眼是目标品类，细看才发现同源**：例如第一眼看到的是一枚发饰，细看才认出灯泡的意象。
  - 把源头原样缩小后贴上去，不算形态重组。

## 第 3 步：写对照提示词

写之前读取 `catalog/README.md`，按“方案探索”一行选卡。

每个方向的提示词 = 公共底座 + 一个专属段落：

```text
<公共底座：Asset type / Input images / Framing / Pose / Expression / Lighting，每个方向逐字相同>

The <object>: <本方向的形态：形状、尺寸（以身体部位为单位）、材质、结构、佩戴方式>
It reads first as <目标品类>, and only on a closer look <与源头的关联>.
It is not <要排除的误读，例如 not a creature, not a sticker>.
```

- 文件命名：`NN-<方向名>.txt`，产物同名，方便并排对比。
- 执行：每个方向调用一次 `gen.py`，参数和底座保持一致：

```text
python <skill目录>/scripts/gen.py --prompt prompts/<NN-方向名>.txt --out-dir output --name <NN-方向名> [--spec <固定设定>] [--ref <角色参考>]
```

`gen.py` 依赖本机已登录的 Codex CLI，以及 Python 3.10+ 标准库。判断成败只看脚本是否打印“完成”以及输出文件是否存在。终端里的 PowerShell profile 报错和生图无关。

## 第 4 步：呈现与收集反馈

- 并排列出各方向，每个写一句取舍，例如“日常感强，但不够特别”“特别，但像玩具”。
- 用户否决时，追问理由，把理由提炼成**原则**，记进 `notes.md`。例如“要先像饰品，象征只能隐约”“不要有空腔”。
- 下一轮的方向必须回应已提炼的原则，不在旧方向上打补丁。用户要求从第一性完整思考时，回到第 2 步重写主张。

## 第 5 步：收敛

- 选定方向后，在同一底座上出亮/灭、正/侧等状态变体，确认细节（线条粗细、尺寸）。
- 定稿后，把形态描述写进固定设定文件或单张提示词，再回到对应流程继续。

## 验收

- [ ] 各方向之间只有探索对象不同，底座没有漂移。
- [ ] 每个方向都符合自己的设计主张。
- [ ] 计数、形状这类细节放大核对。
- [ ] 人体、道具、画面的通用检查同单张流程：五指、接触、无文字水印。

## 决策点

| 决策点 | 选项 | 自主默认 | 即使在自主模式也要问 |
|---|---|---|---|
| 探索轴 | 形状 / 材质 / 位置 / 其他 | 选用户最不确定的那个轴 | 用户的不满说不清落在哪个轴 |
| 方向数 | 2–3 个 | 3 个 | 超过 3 个（额度闸门） |
| 选哪个方向 | 用户挑 / 你推荐 | 按设计主张是否成立，以及是否符合已提炼的原则，给出推荐和理由，但最终仍交给用户挑 | 始终要问：审美选择属于用户 |
| 是否开下一轮 | 继续 / 收敛 | 所有方向都被否时，先提炼原则，再开下一轮 | 已经连续两轮全被否 |

## 交付口径

- 给出各方向的产物路径、设计主张和取舍。
- 明确问用户选哪个，或哪个方向的哪部分值得保留。
- 自主或混合模式下，列出《我替你做的决定》：探索轴、方向数和推荐理由。
