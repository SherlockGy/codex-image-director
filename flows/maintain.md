# 维护本 skill

## 适用

- 把新项目里的生图经验回写到本 skill。
- 调整流程、维度卡或脚本。
- 校准 `SKILL.md` 的触发描述。

选定后回复：“走 维护，依据：用户提到 <原话>；本次改动：<一句话>”。

## 第 1 步：判断新内容放哪一层

| 内容 | 放哪里 |
|---|---|
| 影响流程选择、全局禁止项 | `SKILL.md`（只放短约束） |
| 影响某类任务的执行步骤、验收、返修决策 | 对应的 `flows/*.md` |
| 某个画面维度的写法、有效词、失败模式 | 对应的 `catalog/dimensions/*.md` |
| 为什么这样做的道理 | `README.md` |
| 具体项目的过程记录、某次的来龙去脉 | 不进 skill，留在该项目的 `notes.md` |

- 写入前先提炼成通用规则，不写具体案例。
  - 不写“某角色的发饰多画了一笔”。
  - 改写成“计数类细节必须放大核对”。
- 新失败模式按“现象 → 对策”写进对应维度卡的《常见失败与对策》表。
  - 只有在实际项目里观察到的才写；推测的不写。
- 一条结论有了反例或补充条件，就更新原条目，不另起一条相互矛盾的。

## 第 2 步：同步有意重复的内容

以下内容在多个流程文件里有意重复，改一处必须搜索并同步其他副本：

| 内容 | 出现位置 |
|---|---|
| `gen.py` 命令格式、依赖说明（Codex CLI、Python 3.10+）、成败判断句 | single-image、series-project、explore-variants、edit-refine、redesign |
| `patch_region.py` 命令 | edit-refine |
| 编辑模板固定句 | edit-refine、prompt-language |
| 包装语 | prompt-language、`scripts/gen.py` 的 WRAPPER |
| 通用验收项（五指、接触、物理、无文字水印） | 各流程的验收段 |
| 写实刻度锚定词 | style-realism；series-project 固定设定模板中的引用 |
| 选卡入口句（“读取 catalog/README.md，按 X 一行选卡”） | 各流程的设计步骤；行名必须和 `catalog/README.md` 选卡表一致 |
| 选择审计句式（含“决策模式”） | `SKILL.md` 行为覆写、各流程开头 |
| 决策模式的硬闸门（超过 3 张、自动返修最多 2 轮、始终要问） | `SKILL.md`《决策模式》、各流程《决策点》表 |
| 交付口径里的《我替你做的决定》《可选方向》 | 各流程的交付口径 |

## 第 3 步：脚本维护

- `gen.py` 只用 Python 3.10+ 标准库；`patch_region.py` 用 PEP 723 头声明 pillow，通过 `uv run` 执行。
- 改参数时同步：`-h` 帮助文本、各流程里的命令示例、本文第 2 步的表格。
- 改完至少验证：
  - `python scripts/gen.py -h`
  - 一次 `--dry-run`
  - `uv run scripts/patch_region.py -h`
  - 一次用两张同尺寸图片的真实贴回，确认改动外框只落在区域内
  - 非法输入被拒绝：缺文件、输出已存在、区域越界、尺寸不同
- 真实生图会消耗额度，验证 `gen.py` 的真实调用前先征得用户同意。
- Codex CLI 升级后，要检查 `--json` 事件里是否仍有 `thread.started` 和 `thread_id`，以及生成图目录是否仍在 `$CODEX_HOME/generated_images/<thread_id>/`。

## 第 4 步：自检清单

- [ ] 路由审计：`SKILL.md` 和各流程仍要求打印“走 X，依据：…；决策模式：…；下一步 …”。
- [ ] 规模表：新增流程时更新《任务规模与流程》表，链接都存在。
- [ ] 决策点：新增流程或新的取舍时，在该流程的《决策点》表加一行，写清选项、自主默认和必须问的情况；自主默认不能和 `SKILL.md` 的硬闸门冲突。
- [ ] 单向链：每个流程读完即可执行，只把维度卡当作查写法的资料，不要求把多份文件拼起来才能执行。
- [ ] 维度卡索引：新增或改名卡片时，同步 `catalog/README.md` 的选卡规则和卡片表。
- [ ] 产品化叙述：清理过程记录、案例细节和长段说理；道理放进 `README.md`。
- [ ] 列表层级：有主项和子项时用多级列表，不在一个序号里用分号串联。
- [ ] description：只写触发条件，不写流程和理念。
- [ ] 补丁式维护：同一主题的规则散落在三处以上，或某张维度卡的失败表超过 15 行时，先提议重新归类，再继续追加。
